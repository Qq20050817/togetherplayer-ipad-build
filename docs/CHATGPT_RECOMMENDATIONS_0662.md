# iPad 0.6.62 ChatGPT movie recommendations

Baseline: public Qq20050817/togetherplayer-ipad-build, verified iPad 0.6.61 source 73d2c0bb1b9c07578c147c75783753c2dfeb77f3 and documentation parent efc6e2322387505c699f77dcdcc0e163bb5bf27a. New independent branch feat/ipad-chatgpt-recommendations-20261022, version0.6.62 build122. Rotation and consolidated subtitle import remain included. No server, router, room transport or media playback changes.

WatchMemory owns a separate WatchChatGPTRecommendations controller. TestClient binds it to the existing PlotIntelligence.auth.performInference implementation, its persisted account authorization and selected model. No new credentials, shared tokens, API keys or alternate billing path are introduced. Existing account permission and usage-paused gates are respected; the user must confirm Credits settings before requests.

The recommendation page adds a separate opt-in for sharing watched titles, scores, tags and notes. This consent is independent of sharing plot/subtitle material. Candidates contain film metadata only. No media URLs, movie files, subtitles or room chat are sent. Up to40 recent preference records and120 verified catalog candidates are included; all known watched/dismissed titles are filtered locally before constructing candidates. ChatGPT selects candidates and rewrites a spoiler-free synopsis, reason and personal relation. It does not perform a web search or freely invent film identities. Catalog identity/year remains authoritative. Recommendations cite actual watched record IDs; unknown IDs, duplicate films, unsupported references and malformed outputs are rejected. Semantic quality of generated prose still needs real account/user review.

Successful results retain their verified film metadata, selected model name, generation time and profile fingerprint in a separate on-device cache. Cache survives reopening and source cleanup. Profile changes invalidate stale recommendations and cancel in-flight responses; deleting a watched memory also removes cached reasoning referring to the former profile. Account/consent changes prevent stale output from being committed. Failed manual refresh retains valid current results. Disabled or unavailable generation is visibly labelled as local matching; local results are never labelled ChatGPT-generated.

Automatic generation follows explicit opt-in and can be disabled separately. It is debounced after profile edits, capped at3 automatic attempts per local calendar day, and will not auto retry the same preference profile. Manual retry requires a button press. Opening a page with a current cache does not send another inference request. Existing plot-generation inference can report busy; the recommendations request does not interrupt it or retry silently.

Validation: six native tests cover minimal input/notes, identity and reference rejection, persistence/no resend, consent/account gates, stale response invalidation, and failure retaining cached results. A DEBUG-only offline provider fixture verifies generating cards and reopening saved results through the real UI. Release excludes the fixture. Existing watch memory, rotation and request-support tests remain in the CI selection.

Installer publication is gated on native tests, simulator UI tests, Release device compilation, IPA version/build/catalog checks. Actual ChatGPT account inference, quality of model recommendations and physical-device playback must be checked after installation; build agents do not have the user's on-device authorization. Roll back by installing the prior signed 0.6.61 build without clearing data. Do not uninstall to update if keeping watch history.

Android remains a separate earlier task: 0.6.61 failed its actual video rotation pixel assertion in CI39796323626 and has not been delivered. It has no matching on-device ChatGPT authorization implementation in this iPad baseline. This iPad release does not claim Android ChatGPT integration.
